# iPAS AI 應用規劃師中級備考網站規格

> 本規格描述一個供個人備考使用、可自行部署到網路並跨電腦瀏覽器同步的網站。網站以官方考試範圍和學習指引為題庫依據，提供科目一與科目三的模擬考、主題練習、作答檢討及錯題本。產品決策由使用者與專案協作者共同確認；考試事實以 iPAS 官方資料為準。更新日期：2026-09-29。

| 項目 | 決定 |
|---|---|
| 專案狀態 | 本機功能與 400 題題庫已完成；雲端同步及桌面瀏覽器流程已驗收；尚未部署公開網址 |
| 目標考試 | iPAS AI 應用規劃師中級：科目一與科目三 |
| 網站使用方式 | 每位使用者自行部署一份，該部署供一位使用者使用 |
| 雲端服務 | Supabase 免費方案作為 Auth 與 PostgreSQL 服務 |
| 題庫規模 | 每科 200 題，兩科共 400 題 |

## 問題與目標

考生需要在有限備考時間內練習兩個中級科目，取得接近正式考試的計時與題型體驗，並能在考後理解錯誤原因、追蹤弱點。網站必須在不同裝置上存取同一份個人進度；使用者也希望其他人能下載公開專案，各自部署和保存自己的紀錄。

網站的首要目標是提供可靠、可追溯的題目與解析。歷屆題依官方公告資料收錄；自編題則依官方學習指引中的考點編寫，並查核可信的理論來源。每題都要顯示題目屬於哪個來源類型，以及可追查的出處。

### 解決方案摘要

- 提供科目一與科目三各自獨立的 90 分鐘、50 題計時模擬考。
- 提供固定歷屆試卷、隨機全真模考和按考點練習。
- 模考交卷後顯示分數、及格狀態、作答結果與逐題解析。
- 使用者可選擇將錯題或相關觀念存入個人錯題本。
- 以 Supabase Auth 和 PostgreSQL 儲存使用者資料；使用者自行部署自己的 Supabase 專案。
- 提供資料庫遷移、題庫種子資料、`.env.example` 和部署說明，讓新使用者可依步驟建立個人網站。

## 使用者故事

1. 身為考生，我想用每科完整的計時模考，才能熟悉 50 題與 90 分鐘的考試節奏。
2. 身為考生，我想選擇固定歷屆試卷作答，才能重做官方公告的試題並比較每次表現。
3. 身為考生，我想使用隨機模擬試卷，才能從完整題庫反覆練習不同考點。
4. 身為考生，我想在模考中切換題目、標記待檢查題目並返回修改，才能依正式作答流程管理時間。
5. 身為考生，我想在模考中斷或換裝置時恢復未完成的作答，才能避免遺失進度。
6. 身為考生，我想在交卷後看到成績、每科及格狀態與逐題解析，才能知道是否達到目標並訂正錯誤。
7. 身為考生，我想依科目與考點進行不限時練習，才能針對弱點立即學習。
8. 身為考生，我想將錯題或相關觀念個別加入錯題本，才能決定要保存哪些複習材料。
9. 身為考生，我想查看歷次成績、常錯考點和進度，才能規劃後續複習。
10. 身為考生，我想在自己的不同裝置登入後使用同一個帳號，才能同步模考與學習資料。
11. 身為專案下載者，我想按文件建立自己的 Supabase 專案、載入題庫並部署網站，才能使用一份只屬於自己的備考網站。

## 功能需求與驗收條件

### 1. 帳號與首次設定

- 使用者建立一個帳號並以電子郵件和密碼登入。
- 每份部署只開放首次帳號建立；建立後關閉後續公開註冊。其他使用者要使用服務時，應自行部署另一份專案。
- 註冊及密碼重設使用 Supabase Auth。免費方案的預設郵件服務只能寄給 Supabase 專案團隊成員，因此設定文件需明確要求網站登入信箱與該團隊成員信箱相同；提供 SMTP 的進階設定說明作為替代方式。[Supabase 自訂 SMTP 說明](https://supabase.com/docs/guides/auth/auth-smtp)
- 未登入使用者不得讀取個人作答、錯題本或進度。
- **驗收：**完成設定並建立第一個使用者後，可登入、登出和重新登入；第二個註冊帳號遭拒；密碼重設信可寄至設定允許的信箱。

### 2. 模考

- 提供科目一、科目三獨立的模考入口。
- 可選固定歷屆試卷，保留原年度、梯次、題序、題組關係和題目內容；也可選隨機全真模考。
- 每份正式格式試卷為 50 題、90 分鐘。隨機卷需按科目和學習指引考點抽題，涵蓋題庫主要考點，避免一次模考過度集中於少數考點。
- 題目支援單選、程式碼區塊、附圖和共享情境題組；各題要能獨立選擇一個答案。
- 提供剩餘時間、題號導覽、作答狀態、稍後檢查標記和前後題導覽。
- 使用者可在交卷前修改答案。到時自動交卷；使用者可提早交卷。
- 作答狀態須自動保存到雲端，切換裝置重新登入後可續考；倒數期限以開始時間及考試時長計算，不因重新整理而重置。
- **驗收：**各科開始模考後可看到 50 題及 90 分鐘倒數；重新整理或在另一裝置登入後仍能恢復作答；逾時自動提交；提交前畫面不顯示正解。

### 3. 計分與考後檢討

- 每題等分 2 分，答對得分，答錯或未答得 0 分，不倒扣，總分 100 分。
- 各科達 70 分顯示該科模擬通過；兩科都達 70 分顯示達到機器學習方向證書的模擬門檻。
- 交卷後展示總分、答對數、答錯數、未答數、通過狀態和作答時間。
- 逐題展示使用者答案、正確答案、正解理由、錯誤選項為何不適用、對應考點、來源標示與來源連結。
- 使用者可把題目加入或移出錯題本；若題目有考點標籤，也可獨立將考點加入觀念筆記。
- **驗收：**50 題全部計分總和為 100；70 分門檻判斷正確；交卷後每題的答案、解析和來源可追查。

### 4. 主題練習與複習

- 提供科目和學習指引考點篩選；使用者可選擇單一考點或多個考點練習。
- 練習不限時，作答後立即顯示正確答案、解析和來源。
- 提供錯題本與觀念筆記清單；能依科目、考點、來源類型篩選，能查看題目與解釋。
- 個人學習進度按科目與考點彙整作答量、正確率和最近練習日期。
- **驗收：**可只練習指定考點；作答後可立即訂正；加入的錯題與觀念在重新登入後仍可見；進度數據與實際作答紀錄一致。

### 5. 來源標示

- 每個模考或練習題都顯示來源標籤：
  - 歷屆題：年度、梯次、科目、原卷題號和官方公告連結。
  - 仿歷屆題型：自編標籤，並指出仿照的科目或題型；不得標成官方原題。
  - 依考點新編：自編標籤、學習指引考點與理論參考來源。
- 來源欄位需能在桌面瀏覽器閱讀，不遮住題幹、選項或圖表。
- **驗收：**題庫中每筆題目都有來源類型；無法提供必要來源欄位的題目不得進入正式模考池。

### 數量與組成

| 科目一：人工智慧技術應用與規劃 | 100 | 50 | 50 | 200 |
| 科目三：機器學習技術與應用 | 100 | 50 | 50 | 200 |

官方歷屆題取自資料夾中的 114 年第二梯次與 115 年第一次兩科試題。若官方頁面有更新或新公布試題，維護題庫時更新來源紀錄，不自動把新年度試題混進固定原卷。

### 出題流程

1. 依官方能力鑑定範圍及學習指引建立完整考點清單，包含考點代碼、章節標題和頁碼。
2. 針對每科 50 道「依考點新編」題，從清單選定考點，查核官方文件、標準、論文或技術官方文件等可信來源。
3. 以經查證的概念寫出單選題、唯一正確答案、具迷惑性但錯誤的選項，以及說明正解和其他選項錯誤原因的解析。
4. 針對每科 50 道仿歷屆題型，保留考試題型與難度特徵，但不把自編題標為歷屆題。
5. 逐題記錄來源、學習指引對應考點、查證日期和解析；若來源彼此衝突，以官方與原始一手資料為先並記下採用依據。
6. 核對題目沒有多個合理答案、缺失條件、過時資訊或與指引範圍不符；程式題需核對程式片段及所述輸出。

### 題目內容資料欄位

每題至少包含：唯一識別碼、科目、題幹、選項、唯一正確選項、詳解、錯誤選項說明、來源類型、考點代碼、難度、題目標籤、題組識別碼（若適用）。

歷屆題另記年度、梯次、正式試卷題號和公告試題網址。仿歷屆題另記題型參考依據。依考點新編題另記學習指引章節與頁碼、理論來源標題、URL、來源出版/更新資訊及查證日期。

## 資料與架構決策

### 應用架構

- 使用情境以桌面瀏覽器為準；手機和平板版面相容不列為驗收條件。
- 前端建議採 React、TypeScript 和 Vite，部署為靜態網站；Supabase 提供登入、PostgreSQL 和 Data API。每位使用者各有獨立的前端部署和 Supabase 專案。
- 題目主資料透過版本控管的 SQL 遷移和種子資料匯入每一個 Supabase 專案。使用者作答及個人收藏留在該使用者的資料庫，不回傳至原始碼維護者。
- 建置時可從資料表抽取題目，不由 AI 服務即時產題或生成解析。

### 核心資料實體

- **Question / QuestionGroup：**題目、來源中繼資料、考點標籤、選項與詳解；共享題幹的題目用題組關聯。
- **ExamAttempt / AttemptAnswer：**一次模考或練習工作階段、計時狀態、題目快照、選項作答、標記與計分。
- **SavedQuestion / SavedConcept：**使用者自行加入錯題本的題目和觀念筆記。
- **Topic / Source：**學習指引考點樹，以及官方試題、指引與理論引用。
- **UserProgress：**由作答紀錄計算或更新的考點統計摘要；原始作答紀錄為可追溯來源。

題庫種子資料和可重建的結構需要透過遷移版本管理；升級題庫時不得覆寫使用者已完成的作答快照或收藏。

### 跨裝置同步與網路中斷

- 尚未提交的模考答案和模考截止時間需保存於雲端；不同裝置登入後讀取同一筆進行中的模考。
- 前端可暫存尚未送出的最後一筆操作；重新連線後同步。已提交的模考不可再修改。
- 如果送出時網路中斷，畫面需清楚顯示尚未提交，不得顯示已完成或計分成功。

## 部署與設定流程

每位下載者依序完成：

1. 建立自己的 Supabase 免費專案。
2. 複製 `.env.example` 為 `.env.local`，填入 Supabase 專案 URL 及 publishable key。
3. 使用提供的遷移及種子資料命令初始化資料表、權限政策與 400 題題庫。
4. 使用 Supabase 團隊成員信箱建立唯一網站帳號並測試驗證信；完成後關閉新註冊。
5. 將同一組前端環境變數設定到選定的網站部署服務，完成前端建置與上線。
6. 在 Supabase Auth 登記正式網站網址作為允許的登入和郵件回跳網址。

專案提供清楚的本機執行、初始化、部署、登入設定、備份/匯出和常見錯誤排除說明。Supabase 免費專案若超過一週低活動可能會自動暫停；文件說明如何從 Supabase 控制台恢復。[免費專案暫停政策](https://supabase.com/docs/guides/platform/free-project-pausing)

設定檔契約：

| 變數 | 用途 | 是否可在前端公開 |
|---|---|---|
| `VITE_SUPABASE_URL` | Supabase 專案 API 網址 | 是 |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Supabase 前端 publishable key | 是，必須搭配 RLS 與最小權限 |

`.env.example` 只放變數名稱和假值；`.env.local` 加入 `.gitignore`。資料庫密碼、Supabase secret key、service-role key、SMTP 密碼不得放在前端環境變數、公開原始碼或建置輸出。Publishable key 本身不是使用者資料的存取控制；資料存取依登入身分、資料表授權和 RLS 政策決定。[Supabase API 金鑰安全說明](https://supabase.com/docs/guides/getting-started/api-keys)、[Supabase RLS 說明](https://supabase.com/docs/guides/database/postgres/row-level-security)

## 安全與資料保護

- 所有含使用者資料的公開 schema 資料表均啟用 RLS，並採最小權限 grants。每份部署限一位 Auth 使用者；使用者資料仍需用 `auth.uid()` 驗證資料列擁有者，避免錯誤設定或未授權 API 存取造成外洩。
- 題目和來源屬公開教材資料，可供登入使用者讀取；任何未登入狀態不可讀取個人作答紀錄或修改題庫。
- 公開題庫種子資料不得包含任何個人紀錄或部署者憑證。
- 瀏覽器只使用 publishable key；任何 server-side secret 只能放於伺服器端。首版不需要 secret key，避免引入能略過 RLS 的資料庫權限。
- 不收集報考人身分證、真實姓名或官方考試帳號等非備考必要資料。
- 提供使用者匯出和刪除個人作答及收藏資料的操作方式；刪除帳號時說明 Supabase Auth 帳號與相關個人資料的清除順序。

## 範圍外項目與限制

- 不支援大數據科目、初級科目或其他證照。
- 不包含 AI 即時出題、AI 即時解析、外部 LLM API 金鑰或逐次生成費用。
- 不提供共用多使用者託管服務；每個使用者需自行部署自己的網站與 Supabase 專案。
- 不提供與 iPAS 官方成績系統的整合；模擬成績不能當作正式考試成績或獲證結果。
- 免費方案的配額、郵件政策和閒置暫停規則由服務商決定，可能變更；部署者須自行管理帳號、服務狀態與資料匯出。
- 題庫數量是首版交付目標；若官方試題檔內容抽取或圖片重建需要大量人工整理，不能刪減來源標記或答案解析來假稱完整，應逐題標記尚未完成並補齊後再達成題庫驗收。

## 驗收方式

1. **考試體驗：**桌面瀏覽器可建立 50 題、90 分鐘模考；題號導覽、暫存答案、稍後檢查、重新登入續考和逾時提交行為正確。
2. **評分：**50 題各 2 分，答對、答錯、未答、70 分及格門檻與雙科模擬通過狀態計算一致。
3. **題庫完整性：**兩科各有 100 題官方歷屆題及 100 題自編題；自編題的兩個類型各 50 題。每題具唯一正解、完整解析、考點和必要來源資料。
4. **來源追查：**從任一題目可到達官方試題、學習指引頁面或理論來源；自編新知題有可用的來源 URL 和查證日期。
5. **練習與錯題本：**可按考點練習、立即看解釋、獨立收藏題目或觀念，並在重新登入後保留。
6. **跨裝置：**同一帳號在兩個瀏覽器登入，可讀取同一個進度與未提交模考；一個帳號不能讀取另一個使用者 ID 的資料。
7. **部署：**新部署者可只依文件建立 Supabase 專案、載入遷移與種子、設定環境變數、建立唯一使用者並上線；原始碼與版本控制狀態沒有真實憑證。
8. **安全：**以未登入與錯誤使用者身分驗證 RLS 拒絕個人資料存取；檢查建置產物及公開 Git 內容不含 secret/service-role key 或資料庫密碼。
